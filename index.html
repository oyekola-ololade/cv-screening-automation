System flow

From intake to review.

The workflow separates input handling, persistence, AI evaluation, and response logic. Its strongest design choice is the visible failure route: bad extraction becomes a reviewable record rather than a missing candidate.

01 / TRIGGER

Application webhook

Receives candidate fields and supplied CV text.

02 / NORMALIZE

Prepare candidate data

Creates a consistent object for downstream nodes.

03 / CONTROL

Assess extraction

Checks whether the available text is usable.

Implemented

What the file proves.

Every item below maps to a named node or explicit code path in the sanitized workflow export.

A / INTAKE

Structured candidate record

Form fields and supplied CV text are normalized into a consistent object for downstream steps.

B / CONTROL

Extraction confidence route

Missing or insufficient text is marked low confidence and redirected to a dedicated failure path.

C / DATA

Two-stage sheet updates

A candidate is appended before evaluation, then updated with the validated screening result.

D / AI

Explicit scoring contract

The prompt requests JSON with a 0–100 match score, pass/fail constraint result, reason, and evidence.

E / SAFETY

Protected traits excluded

The evaluation prompt instructs the model not to use protected characteristics in scoring.

F / VALIDATION

Defensive result parsing

Output is parsed, normalized, length-limited, and score-clamped before persistence.
